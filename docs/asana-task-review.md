# Staff task review

Admins can open **Task review** (`#/taskreview`), choose a date and minimum task age (default six calendar days), and select **Pull from Asana**. The page shows progress while a server-side read runs; it can be closed and reopened. Select a staff member, due/overdue work, two or more deadline changes, two or more postponements, or tasks whose history needs review. Expand a task to see its deadline history and the actor/time of each change. No Asana write or Slack send is performed.

Uses the existing server `ASANA_TOKEN`; it must be allowed to read tasks and stories in the selected projects. Optional `ASANA_REVIEW_PROJECT_GIDS` is a comma-separated project allowlist. Its default is the five projects used in the original report: LIT Tasks, Partners List, Indian Clients, Skyline World – Client Ops and Michael. It is independent of the existing employee task/EOD project settings. Tokens never enter the browser.

Collection follows all pages, deduplicates project tasks and recursively reads subtasks, including open children of completed parents. Dates, reads and seven-day windows use `TZ_OFFICE` (default Asia/Kolkata). Rate limits are retried with pacing. Only one collection runs per process, and a complete report is cached for five minutes. Successful reports and short-lived story caches survive restarts in additive `asana_review_reports` and `asana_review_stories` SQLite tables. Failed collections leave prior saved reports unchanged; failed per-task activity reads show unknown history. No employee/attendance tables are updated by this feature.

Past-date reports rewind available `marked_complete`, `marked_incomplete` and `due_date_changed` activity. They are reconstructions, not guaranteed historical snapshots: deleted tasks, removed project membership, consolidated/missing stories and edits during collection may be absent. Asana does not provide an atomic history read. Assignee, project names and tags are explicitly current; the page does not claim the current employee owned a task throughout its age. Task age measures time since creation, not inactivity or time overdue. Unknown historical pending status is shown separately and excluded from the confirmed pending count. Future report dates are rejected. Today means the current observed state, past days mean end of day in the office timezone.

Deadline counts cover the report date and preceding six days. Only structured due-date differences count; start-only changes do not. Adding/removing a deadline counts as a date change, but only moving an existing deadline later counts as postponement. Timeline labels “Due today” and “Due in future” are relative to each change's local calendar day. Structured old/new values unavailable from Asana remain unknown; localized story text is displayed as context and never parsed into dates.

API: admin-only `GET /api/asana-review?date=YYYY-MM-DD&minAge=6`, `POST /api/asana-review/refresh` with `{date,minAge}`. Status and previous report are returned by GET. Results include observation interval, project scope and row-level history availability. Safety bounds (500 pages per endpoint, 20,000 traversed tasks, 2,000 history candidates) fail visibly rather than silently truncating. A restart interrupts an in-flight read; the previous saved result remains and the administrator can pull again.

Source API documentation: https://developers.asana.com/reference/getstoriesfortask and https://developers.asana.com/reference/stories . The full activity feed is requested without a comment-only filter.
